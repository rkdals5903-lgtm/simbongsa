git fetch: 먼저 원격 저장소에 새로운 코드가 얼마나 올라왔는지 확인합니다.
git log -p main..origin/main: 어떤 내용이 바뀌었는지 꼼꼼히 살펴봅니다.
git merge (또는 pull): "아, 바뀐 내용이 안전하네!" 싶을 때 내 코드에 합칩니다.

git clone은 public 일 경우에 ssh나 토큰 없이 깃허브 주소만으로 연동이 가능하다!
---------------------------
feature/: 새로운 기능을 개발할 때

fix/: 버그를 수정할 때

docs/: 문서만 수정할 때

chore/: 기능과는 상관없는 자질구레한 설정(라이브러리 추가 등)을 할 때

브랜치 이름은 feature/이름 처럼 슬래시를 사용하면 관리하기가 좋다.

git push -u origin feature/vla # 새로운 브랜치 생성하고 푸쉬할 경우에 사용
